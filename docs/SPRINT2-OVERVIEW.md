## Package B: easy way back, verbose help, settings, history (items 3, 5, 6, 9)
- Judge: 7/10 first round; second round addresses its findings.
- **Built.** Esc/Tab on Search return to the results; Search title and bottom bar say so ("F3 settings · F4 history · F1 help" on Search, since letters are text there; "S settings · H history · ? help" elsewhere). Results title carries "/ or Esc: search · ? help". `Screen::Settings` (`S`/F3, `commands/settings.rs`): Volume (left/right, -/+), History file (Enter shows path and how to change it: `TERMUSIC_HISTORY` or `history_path` in settings.json), Clear history (Enter twice). `Screen::History` (`H`/F4, `commands/history.rs`): last 10 tracks, most recent first, no duplicates, in `history.json` next to settings.json. Enter replays that entry and queues the list in history order, so next tracks follow it. Help lists commands in groups (Playback, Queue, Navigation, Screens, Other fallback) plus a Keys section (Esc, Tab, F1-F4, j/k, PgUp/PgDn, g/G, Enter) and scrolls (j/k, PgUp/PgDn, g/G).
- **Structure.** Overlays (Help, Settings, History) sit on `App::stack`; Esc pops one, re-opening a screen already below truncates instead of nesting; `/`, `P`, `F2` call `close_all` first, so the list's selection is restored, and a track that starts meanwhile moves the saved selection (`saved_sel`) so the list follows the playing track. `src/history.rs`: `Entry { track, position_secs }` (flattened serde, old plain-track files still load), `push`, `load`, `save` (atomic, returns the error), `resume_point` (under 10 s or within 10 s of the end restarts). The position is stored when the track changes or the app quits and replay passes `--start=N` (`Player::play(.., start)`). The history path is injected: `App::with_paths(settings, path)`; `Settings::history_file(env, dir)` is pure; tests use `App::blank()` with no path. All writes (history, volume) run through `bg` (spawn_blocking, serialized by a mutex, inline when no runtime); failures arrive as `Msg::SaveFailed` and show in the status bar. Exit saves synchronously in `App::shutdown`.
- **Deviations.** Command groups are a name table in `ui.rs`, not a `GROUP` const per command file. Help now scrolls instead of fitting 80x24. Settings rows are an enum (`Row`), not a bigger Loop-mode setting (kept small as asked).
- **Known gaps.** Position is whole seconds taken from the once-a-second poll, so it can be about a second stale; a crash (SIGKILL) loses the position of the playing track, not the list. `bg` writes are ordered by mutex acquisition, not strictly FIFO, but volume presses are 200 ms apart. History is not shared between two running instances (last writer wins). Replay position was verified by unit tests and `mpv_command` args only, not by ear against a real track. `Settings::save` still swallows errors (only history failures are surfaced).

## Package C: preload + crossfade (item 1)
- **Built.** `Player` now holds `current` and `next` (`Option<Running>`; `Running` carries its own socket, id, title and watchdog). Within `PRELOAD_SECS` (20) of the end of the current track (duration known from the poll) `App::sync_preload` starts the next track's mpv with `--pause=yes --volume=0`, its own socket (`termusic-mpv-<pid>-<n>.sock`, counter in `Player`) and its own watchdog. In the last `CROSSFADE_SECS` (4) the preload is unpaused and `tick` sends a volume step every 200 ms (equal-power curve, `fade_volumes`, user volume is the ceiling). When the fade ends, or the old mpv exits by itself, `tick` reports a normal end; `App::next` advances the queue and `play_current` calls `Player::promote`, which kills the old instance and makes the preload current (so `TrackStarted`, history and selection take the normal path). Manual `n` also promotes a ready preload instantly; anything else (prev, new Enter, history resume with a start offset, Loop::One) spawns cold.
- **Queue changes.** `Queue::peek_next` says what `next` would play (none on Loop::One, at the end, or on a shuffled Loop::All wrap). Each frame the preload is compared with it and discarded on mismatch, so skip, prev, shuffle, loop and new queues need no hooks. `tried` stops a second preload of the same track (also after a dead preload; cleared whenever a track starts).
- **Failure.** A preload that dies is dropped silently and the cold path runs later. `promote` sends volume then unpause first; if the socket is not up yet it drops the preload and returns false (cold spawn), so a paused mpv is never left as current. Volume keys during a fade are applied by the next fade step instead of directly.
- **Also.** `App::shutdown` takes the IO lock before its synchronous save. Unit tests never start a real mpv: `mpv_program()` is `true` under `cfg(test)`.
- **Tests.** `should_preload`, `fade_volumes`, socket naming, stop kills both instances, dead preload dropped and not retried, natural end keeps the preload, promote needs a matching ready preload, `peek_next`.
- **Verified live in a pty** (real mpv + yt-dlp, scratch config dir, 25% volume): on a 60 s track the second mpv appeared (paused, volume 0, duration loaded) at 40 s, about 20 s before the end; at 56 s the fade started and the IPC volumes read back as old 23/20/15/10/5 and new 5/9/15/20/23/24/25, with the new track at 3.7 s position when the old one was killed; one mpv remained afterwards; a second transition (a 247 s track, reached by seeking) behaved the same; nothing was left running after Ctrl-C.
- **Not verified.** The crossfade by ear (only the volumes and positions read back over IPC). Pausing during a fade, user volume changes during a fade on a real track, and a preload that fails on a real unavailable video.
- **Known gaps / shortcuts.** Fade timing depends on the 1 s position poll, so the fade can start up to a second late (its length is shortened to what is left). No preload on a shuffled Loop::All wrap. Readiness of a preload is not polled (a socket that answers is enough). Pause during a fade pauses only the old track. A preload is not shared across a Loop change back and forth within a frame.
- **Judge round 2 fixes (7/10).** Pause during a fade pauses and resumes the preload too, and the fade clock skips the paused time; no fade starts while paused. Any seek cancels an active fade (preload re-paused at volume 0, current back to the user volume); after the poll, `left > CROSSFADE_SECS` cancels a fade and `left > PRELOAD_SECS` drops the preload (and clears `tried`, so it preloads again near the end). Fade progress stays wall-clock based (cancel logic covers the poll lag). The watchdog traps HUP so its socket cleanup survives a terminal hangup after `kill -9`. A promoted track's `started` is the promotion time, so an immediate exit counts as a failure. The mpv binary is a `Player::mpv` field (default `mpv`); `App::blank()` sets it to `true`, replacing the `cfg!(test)` hack. `shutdown` comment now says it waits only for a write already running. New tests use a `UnixListener` stand-in for the mpv socket: promote success, `step_fade`, discard restoring volume, pause and seek during a fade, far-from-end cancel. Still not verified live: pause/seek during a fade on a real mpv, and the HUP trap in a real terminal.
